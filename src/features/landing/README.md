# landing

The front page's working part, after the Seal prototype.

- `PostingForm`: the whole front page. The headline copy (its `children`) and the input on the left; a large ink guilloche seal on the right that redraws from what you type, with `figures` in its centre; then an ink band of sample postings, each with its own seal. On phones: input, samples, then the seal. Three tabs pick the input: a posting (`POST /api/maps`), a PDF (`POST /api/maps/pdf` with form data `file`) or a topic. Postings and PDFs always build one private map. Only a topic shows the size (decide for me, program, one course) and length (short path or full degree) toggles, and goes to `/api/programs` (or `/api/maps` for one course). `request.ts` builds the request and reads the reply: `{ programId }` goes to `/program/[id]`, `{ mapId }` or `{ id }` to `/map/[id]`. It checks size and type first, so nobody waits for a no. If the response has `{ error }` as a sentence, it shows that; otherwise a built-in message. Waiting shows real elapsed time, not fake progress. A sample builds straight away.
- `LandingFigures` (server): Alberta's unemployment rate in the seal's centre, live from Statistics Canada via `@/features/labour`. `LandingFiguresSource` is the fine print (tables, the Calgary average, retrieval date). Both render nothing if StatCan has never answered.
- `HowItWorksButton` (from `@/features/landing/client`): a short dialog on the front page and the map header. What the AI does and what code does, plus three measured figures copied from `docs/eval-results.md`.
- `SampleFromLink`: `/?sample=<id>` fills in that sample and switches to the posting input.
